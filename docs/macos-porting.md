# macOS 连接后台设计

当前状态见 [Mac 开发与测试](macos-development.md)。旧的 0.2.7 迁移包不再是开发基线；公共核心已经剥离，Mac 平台目录已加入主干。下一阶段要完成 `IConnectionBackend`，不再重写公共业务。

## 引擎与权限

内部自用版本优先使用本机官方 OpenVPN 2.x 进程的管理接口，复用 `ManagementProtocol`、`ManagementStartup` 和 `ManagementCommands`。启动时探测实际安装位置、架构、版本及二进制信任，不能把 Windows 路径、DCO 驱动或命名事件参数带到 Mac。

AppKit 界面保持普通用户权限；VPN 后台独立管理隧道、路由和 DNS。macOS 13 及以后的后台服务可使用 [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)。待目标 Mac 上确认签名身份、后台授权与发布方式，接入受控的 XPC/Unix IPC。不得用通用 shell/root 执行器替代专用权限服务。

后台验证客户端身份、会话归属、导入配置和受控引擎路径。配置仍经公共允许列表解析，拒绝脚本、插件、嵌套配置和自定义管理接口。提权之前，将经校验的配置及依赖放入后台独占的快照，避免检查后文件被替换。不能把管理员执行目标指向用户可替换的任意可执行文件。

Keychain 由用户端读取；后台不能假定 root 会话可以读取用户的 Keychain。登录资料仅通过已验证的本地会话传输并及时清理，不进入 argv、日志、临时认证文件、源码或普通设置。

## 生命周期与认证

`Start` 接受请求后显示启动中，只有收到官方核心真实 `CONNECTED` 事件才显示已连接。管理接口使用每次会话独立的口令和受限传输，禁止暴露到外网；身份验证后主动放行 HOLD，逐条等待命令确认，不重发响应不明的认证命令。

密码后直接拼接六位验证码，无分隔符。自动验证码继续使用 `TotpOtpProvider` 和 `TotpRepository` 的周期防复用记录，临近过期等待时响应取消。手动验证码一次性使用；认证拒绝停止自动重连，手动断开或退出不能重新连接。

`Stop` 只请求取消，不在 UI 线程 join 子进程或阻塞 socket。正常退出先请求官方核心结束，超时仅回收本应用拥有的进程组；不能结束其他 VPN 客户端。父界面退出、权限拒绝、启动超时和重复点击都需有确定的最终状态。

## 分流、DNS 与验收

保留 `SplitTunnelPolicy()` 的默认路由过滤，不添加全流量接管。域名连接先解析，成功更新持久缓存；仅解析失败且用户开启回退时使用已缓存的 IP，不放松服务端证书身份校验。

Mac CLI 的 DNS 配置必须单独实现和实测。仅允许应用控制的系统 DNS 处理，记录本应用的更改，并在断开、失败、退出和崩溃后恢复；不能开放用户配置的任意 up/down 脚本。需验证公司域名、内网 IP、公网默认路由和睡眠唤醒。

先运行公共核心、Mac 平台测试；然后用强制环回目标和公开合成凭据探测管理认证、HOLD 放行、命令确认、取消与重复启动。以上通过后，才由用户在 Mac 本机导入公司配置、当前绑定及登录资料实连。分别记录离线测试、环回引擎和公司 VPN 的结果，不互相替代。

正式 Developer ID 签名、公证、安装升级、后台授权的持续有效性以及 Network Extension 路线另行确定；当前构建产物仅做本机 ad-hoc 签名。项目没有声明开源许可证，不擅自新增授权或捆绑未核对许可的 VPN 二进制。
